# Worker roles

Select only roles that add independent value. GPT-6 Sol MAX remains the lead for every role combination. A role is a prompt pattern, not a worker that must be started. Give each worker the named boundary, relevant context, edit permission, expected output, and a stopping condition; ask it to report evidence and uncertainty concisely.

| Role | Recommended model and effort | Bounded objective | Context to provide | Expected output |
| --- | --- | --- | --- | --- |
| `repository-explorer` | GPT-6 Luna HIGH | Map the named subsystem's entry points, conventions, and relevant symbols. | User goal, starting paths or search terms, applicable project docs. | Key paths and symbols, established patterns, unresolved locations. |
| `call-site-analyzer` | GPT-6 Luna HIGH | Find consumers and contracts affected by one named API, symbol, or behavior. | Changed symbol or contract, affected package boundary. | Call sites with paths, contract assumptions, likely impact. |
| `test-analyzer` | GPT-6 Luna HIGH | Locate relevant tests, fixtures, scripts, and existing coverage gaps. | Target behavior, affected paths, project test tooling. | Relevant tests and commands, focused gaps, no invented checks. |
| `dependency-analyzer` | GPT-6 Luna HIGH | Trace dependencies and configuration connected to one named change. | Affected module, package or service names, relevant manifests. | Dependency map, version or configuration constraints, supporting paths. |
| `implementation-planner` | GPT-6 Luna MAX | Compare plausible ways to implement a bounded feature or fix. | Requirements, relevant files, existing conventions, known constraints. | Recommended path, affected files, invariants, tradeoffs, open questions. |
| `bug-investigator` | GPT-6 Luna MAX | Test root-cause hypotheses for a specific symptom or failing case. | Reproduction or logs, affected flow, relevant code and tests. | Evidence-backed cause or narrowed hypotheses, reproduction and checks. |
| `edge-case-reviewer` | GPT-6 Luna MAX | Examine boundaries and failure paths of a proposed change. | Proposed behavior or diff, input and lifecycle contracts. | Concrete edge cases with locations and focused verification ideas. |
| `regression-reviewer` | GPT-6 Luna MAX | Check changed and neighboring paths for unintended behavior. | Actual diff, existing behavior, known consumers and tests. | Actionable regressions with evidence and focused checks. |
| `adversarial-reviewer` | GPT-6 Luna MAX | Challenge security, permission, data-integrity, and misuse assumptions in a high-impact change. | Threat or misuse boundary, actual design or diff, relevant contracts. | Reproducible failure paths or supported risk findings, not speculation. |
| `concurrency-specialist` | GPT-6 Sol MAX, only when justified | Resolve a concrete difficult race, ordering, retry, cancellation, or shared-state question. | Specific interleaving or invariant, relevant state and prior Luna findings. | Reasoned failure sequence or invariant, minimal fix or verification plan. |
| `database-specialist` | GPT-6 Sol MAX, only when justified | Resolve a non-obvious transaction, constraint, migration, query, or consistency question. | Schema, query or migration, data-integrity requirement, prior Luna findings. | Contract-level conclusion, affected operations, validation or rollback concern. |
| `architecture-specialist` | GPT-6 Sol MAX, only when justified | Analyze a difficult cross-module design or invariant with competing choices. | System boundaries, requirements, relevant modules, prior Luna findings. | Decision options, invariants, tradeoffs, recommended narrow path. |
| `bounded-implementer` | GPT-6 Luna HIGH for mechanical edits; GPT-6 Luna MAX for bounded reasoning | Implement the settled design within exclusive file or module ownership. | Accepted plan, exact files, coding conventions, relevant checks. | Scoped diff summary, checks run, assumptions and unresolved issues. |

Use Luna HIGH for mechanical discovery, Luna MAX when deeper bounded analysis can change the result, and an additional Sol MAX specialist only when Luna is insufficient for a specific difficult question. The lead verifies all worker findings and integrates the final implementation. Do not overlap concurrent writers or duplicate scopes unless an independent second opinion is intentionally useful.
